# 사용자·권한 관리 운영 검증 시나리오

## 1. 가입과 Buyer 요청

- 요청자 가입: 이름·부서·연락처 입력 후 즉시 요청자 권한으로 로그인된다.
- Buyer 요청 가입: 희망 담당 카테고리를 하나 이상 선택하지 않으면 가입이 진행되지 않는다.
- 가입 완료 후 `buyer_role_requests`에 대기 상태와 희망 카테고리가 기록된다.

## 2. 승인 흐름

- 팀장 또는 관리자가 Buyer 요청을 승인하고 사유를 입력한다.
- 승인된 사용자는 Buyer가 되고, 희망 카테고리가 자동 배정된다.
- 반려·보류 시 역할은 요청자로 유지되고 알림과 감사로그가 남는다.

## 3. 권한 범위

- 팀장은 요청자·Buyer의 역할과 활성 상태만 변경할 수 있다.
- 팀장은 팀장·관리자 계정을 변경할 수 없다.
- 관리자는 전체 역할을 관리할 수 있으나 본인 계정은 변경할 수 없다.

## 4. 비활성 사용자

- 비활성화에는 변경 사유가 필요하다.
- 비활성 계정은 로그인과 신규 배정 대상에서 제외된다.
- 과거 구매·계약·감사 이력은 유지된다.

## 5. 알림과 이력

- Buyer 요청 처리 시 요청자 알림 센터에 결과가 나타난다.
- 알림은 본인만 읽음 처리할 수 있다.
- 사용자 상세 화면과 권한 변경 이력에서 변경 사유를 확인할 수 있다.

## 6. AD 준비

- 사용자 프로필에 이메일, AD Object ID, 마지막 동기화 시각이 존재한다.
- 실제 동기화는 회사 정책 승인 및 API 권한 설정 뒤에만 활성화한다.
