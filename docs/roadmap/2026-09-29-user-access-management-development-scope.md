# NP MKT 사용자·권한 관리 개발 단계별 범위

## 목표

사용자 권한을 Supabase SQL 수동 처리에서 웹 관리 화면으로 전환한다. 신규 사용자는 즉시 요청자로 이용할 수 있고, Buyer 요청·카테고리·계정 상태·권한 변경을 팀장과 관리자가 관리한다.

## 단계 1. 데이터 기반 및 보안 정책

### 범위

- profiles 확장: 부서, 연락처, AD 연동 필드, 최근 로그인·비활성화 정보
- Buyer 요청, Buyer 카테고리, 감사 이력, 시스템 알림 테이블 생성
- 역할별 RLS 정책·DB 검증 함수 적용
- 가입 트리거를 요청자 활성화 + Buyer 요청 생성 흐름으로 확장
- 기존 사용자 데이터 마이그레이션 스크립트 작성

### 완료 기준

- 신규 가입은 즉시 요청자·활성 계정으로 생성된다.
- Buyer 요청은 실제 역할과 분리돼 pending 상태로 저장된다.
- 팀장은 요청자·Buyer만, 관리자는 모든 역할을 변경할 수 있다.
- 권한·상태 변경이 감사 이력에 기록된다.

### 사용자 확인 사항

- Supabase SQL 마이그레이션 실행 필요
- 기존 사용자 부서·연락처 초기 입력 필요

## 단계 2. 회원가입·내 프로필

### 범위

- 회원가입 입력: 이름, 이메일, 비밀번호, 부서, 연락처, Buyer 요청, 희망 카테고리
- 가입 후 즉시 로그인
- 내 프로필 화면: 기본정보·현재 권한·Buyer 요청 상태·담당 카테고리
- 본인 부서·연락처 수정
- Buyer 요청 신규 생성·취소

### 완료 기준

- 가입 양식 검증과 중복 이메일 처리 동작
- Buyer 요청이 승인 대기 목록에 저장됨
- 본인 외 정보는 수정할 수 없음

## 단계 3. 사용자 목록·상세 관리

### 범위

- 사용자 목록: 검색, 역할·상태·Buyer 요청·카테고리 필터
- 사용자 상세: 기본정보, 권한·카테고리, 업무 현황, 변경 이력
- 계정 활성화·비활성화
- 역할 변경과 Buyer 카테고리 다중 지정
- 팀장/관리자별 제어 제한 UI 적용

### 완료 기준

- 비활성 사용자는 로그인과 신규 자동 배정에서 제외됨
- 기존 구매·계약 이력은 유지됨
- 팀장이 관리자 권한을 변경하려 하면 DB와 화면 모두 차단됨

## 단계 4. Buyer 요청 승인함·알림

### 범위

- Buyer 권한 요청함: 대기·보류·승인·반려 목록과 필터
- 승인·반려·보류 처리, 사유 입력
- 승인 시 Buyer 역할·카테고리 반영
- 요청자 시스템 알림 생성·읽음 처리
- 변경 이력 타임라인

### 완료 기준

- 카테고리 없는 Buyer도 승인 가능
- 승인·반려·보류 사유와 처리자가 모두 기록됨
- 요청자가 처리 결과를 내 프로필에서 확인 가능

## 단계 5. 구매·계약 업무와 연계

### 범위

- 활성 Buyer만 카테고리 자동 배정 후보로 사용
- 비활성 Buyer가 담당한 미처리 구매·계약 건을 관리자가 재배정
- 사용자 상세에서 담당 구매 요청·계약·지급 대상 요약 표시
- 카테고리 변경 시 신규 요청 자동 배정 규칙 재평가

### 완료 기준

- 비활성 Buyer는 신규 건에 자동 배정되지 않음
- 과거 업무 이력의 담당자는 변경하지 않음
- 재배정 이력이 감사 로그에 남음

## 단계 6. AD 연동 준비 및 운영 안정화

### 범위

- AD 연동 대상 필드와 동기화 상태 화면 제공
- AD 연동 전 수동 CSV 검증 도구(선택)
- 권한 변경 감사 로그 조회·CSV 내보내기
- 오류·권한 거부·미처리 요청 모니터링

### 완료 기준

- AD 연동 도입 시 이메일/AD 객체 ID를 기준으로 충돌 없이 연결 가능
- 운영자가 권한 변경 이력을 기간·사용자별로 조회 가능

## 구현 우선순위

1. 단계 1: 보안·데이터 기반
2. 단계 2: 가입과 내 프로필
3. 단계 3: 사용자 관리 화면
4. 단계 4: Buyer 요청 승인과 알림
5. 단계 5: 구매·계약 연계
6. 단계 6: AD 연동 준비

초기 운영에 필요한 최소 범위는 단계 1~4이며, 이후 단계 5~6은 기존 구매·계약 데이터와 AD 정책 확정 후 진행한다.
