# NP MKT 사용자·권한 관리 화면 설계서

## 1. 목적

Supabase에서 직접 처리하던 사용자 계정·권한 관리를 시스템 화면으로 전환한다. 신규 사용자는 요청자 권한으로 즉시 이용하고, Buyer 권한 요청·계정 상태·담당 카테고리·권한 변경 이력을 팀장과 관리자가 통제한다.

## 2. 역할과 관리 범위

| 역할 | 사용자 조회 | 요청자·Buyer 변경 | 관리자 변경 | 계정 비활성화 | Buyer 요청 승인 |
|---|---:|---:|---:|---:|---:|
| 요청자 | 본인 | - | - | - | - |
| Buyer | 본인 | - | - | - | - |
| 팀장 | 전체 | 가능 | 불가 | 가능 | 가능 |
| 관리자 | 전체 | 가능 | 가능 | 가능 | 가능 |

- 팀장은 관리자 권한을 부여·회수할 수 없다.
- 비활성화 사용자의 과거 구매·계약·승인 이력은 유지한다.
- 비활성 사용자는 신규 Buyer 자동 배정과 권한 요청 승인 대상에서 제외한다.

## 3. 화면 목록

| ID | 화면 | 접근 역할 | 목적 |
|---|---|---|---|
| U-01 | 사용자 목록 | 팀장, 관리자 | 사용자 검색·필터·상태 확인 |
| U-02 | 사용자 상세 | 팀장, 관리자 | 프로필, 권한, 담당 카테고리, 활동·변경 이력 확인 |
| U-03 | Buyer 권한 요청함 | 팀장, 관리자 | Buyer 요청 승인·반려 |
| U-04 | 권한·상태 변경 패널 | 팀장, 관리자 | 역할, 계정 상태, 담당 카테고리 변경 및 사유 입력 |
| U-05 | 내 프로필 | 전체 | 본인 부서·연락처·권한·Buyer 요청 상태 확인 |
| U-06 | 회원가입 | 비로그인 | 이름·이메일·비밀번호·부서·연락처·Buyer 요청·카테고리 요청 입력 |

## 4. U-01 사용자 목록

### 4.1 상단 구성

- 제목: `사용자·권한 관리`
- 보조문구: `계정 상태, 업무 권한, Buyer 요청을 관리합니다.`
- 우측 요약 카드: 전체 사용자 / 활성 사용자 / Buyer 승인 대기 / 비활성 사용자
- 팀장·관리자만 메뉴에 노출한다.

### 4.2 검색·필터

| 조건 | 값 |
|---|---|
| 통합 검색 | 이름, 이메일, 부서, 연락처 |
| 역할 | 전체, 요청자, Buyer, 팀장, 관리자 |
| 계정 상태 | 전체, 활성, 비활성 |
| Buyer 요청 | 전체, 요청 없음, 승인 대기, 승인, 반려 |
| 담당 카테고리 | 전체 또는 카테고리 선택 |

### 4.3 목록 컬럼

| 컬럼 | 표시 방식 |
|---|---|
| 이름·이메일 | 이름과 이메일 2줄 표시 |
| 부서·연락처 | 미입력 시 `-` |
| 현재 역할 | 역할 배지 |
| 계정 상태 | 활성/비활성 배지 |
| Buyer 요청 | 요청 상태 및 요청일 |
| 담당 카테고리 | 최대 2개 노출, 나머지는 `+N` |
| 최근 로그인 | 없으면 `로그인 이력 없음` |
| 관리 | `상세 보기` 버튼 |

행 또는 상세 보기 선택 시 U-02를 연다.

## 5. U-02 사용자 상세

### 5.1 헤더

- 이름, 이메일, 역할, 계정 상태 표시
- 가능한 관리 행동: `권한 변경`, `계정 비활성화/활성화`
- 팀장이 관리자를 변경하려 할 경우 버튼을 숨기고 안내 문구를 표시한다.

### 5.2 탭

| 탭 | 내용 |
|---|---|
| 기본 정보 | 이름, 이메일, 부서, 연락처, 가입일, 최근 로그인일 |
| 권한·카테고리 | 현재 역할, Buyer 요청 상태, 담당 카테고리, 적용일 |
| 업무 현황 | 담당 구매 요청, 유지보수 계약, 미처리 지급 대상 건수 |
| 변경 이력 | 권한·상태·카테고리 변경 전후 값, 사유, 변경자, 일시 |

비활성 사용자가 담당한 업무 현황에서는 `과거 이력 보존 · 신규 자동배정 제외` 문구를 표시한다.

## 6. U-03 Buyer 권한 요청함

### 6.1 목록

- 승인 대기 요청만 기본 표시하고, 승인/반려 이력도 필터로 조회한다.
- 컬럼: 요청자, 이메일, 부서, 연락처, 요청 카테고리, 요청일, 현재 역할, 처리 상태

### 6.2 처리

| 행동 | 결과 | 필수 입력 |
|---|---|---|
| 승인 | 역할을 Buyer로 변경, 선택 카테고리 적용 | 승인 사유 선택 입력 |
| 반려 | 요청자는 유지, 요청 상태 반려 | 반려 사유 필수 |
| 보류 | 역할은 유지, 요청 상태 보류 | 보류 메모 필수 |

- 카테고리를 선택하지 않은 요청도 Buyer 승인 가능하다.
- 승인·반려·보류 모두 변경 이력으로 남긴다.

## 7. U-04 권한·상태 변경 패널

### 7.1 변경 항목

- 역할: 요청자 / Buyer / 팀장 / 관리자
- 계정 상태: 활성 / 비활성
- Buyer 담당 카테고리: 다중 선택, 선택하지 않아도 저장 가능
- 변경 사유: 필수 입력

### 7.2 검증 규칙

1. 팀장은 요청자와 Buyer 사이에서만 역할 변경 가능하다.
2. 팀장이 팀장·관리자 계정을 수정하려면 계정 상태와 Buyer 카테고리만 수정 가능하다.
3. 관리자는 모든 역할을 변경할 수 있다.
4. 자기 자신의 관리자 권한을 해제하거나 자기 계정을 비활성화할 수 없다.
5. 비활성화 확인 창에는 과거 이력이 유지되고 신규 자동배정에서 제외된다는 내용을 표시한다.

## 8. U-05 내 프로필

- 로그인한 전 사용자가 접근 가능하다.
- 이름·이메일·현재 역할·계정 상태·부서·연락처·담당 카테고리·Buyer 요청 상태를 표시한다.
- 부서와 연락처만 직접 수정 가능하다.
- Buyer 요청이 없거나 반려된 요청자는 `Buyer 권한 요청` 버튼으로 U-03에 새 요청을 생성한다.

## 9. U-06 회원가입

### 9.1 입력 항목

| 항목 | 필수 | 규칙 |
|---|---:|---|
| 이름 | 예 | 2~50자 |
| 회사 이메일 | 예 | 이메일 중복 불가 |
| 비밀번호 | 예 | 최소 8자 권장 |
| 부서 | 예 | 직접 입력 |
| 연락처 | 예 | 전화번호 형식 검증 |
| 업무 권한 선택 | 예 | 요청자 / Buyer 권한 요청 |
| 담당 카테고리 요청 | 아니오 | Buyer 권한 요청 시 다중 선택 |

- 가입 직후에는 항상 활성 요청자 계정으로 로그인한다.
- Buyer 권한 요청은 현재 역할을 바꾸지 않으며 U-03의 승인 대기 목록에 생성한다.

## 10. 공통 상태 및 알림

- Buyer 요청 승인·반려 시 신청자에게 시스템 알림을 생성한다.
- 이메일 발송은 Outlook 연동이 확정되기 전까지 시스템 알림으로 우선 제공한다.
- 사용자·권한 관리 화면의 변경은 모두 감사 이력으로 남기고 수정·삭제할 수 없다.
