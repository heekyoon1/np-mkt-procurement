# NP MKT 구매업무 통합시스템 PRD

문서 버전: v0.1  
작성일: 2026-08-18  
문서 목적: 로컬 프로토타입 구현 및 Vercel·Supabase 배포를 위한 제품 요구사항 정의

## 1. 제품 개요

NP MKT 구매팀의 구매요청, 다중 견적, 번들 구성, 가격 계산, 승인, 발주 진행, 쉽컴펌, 구독·유지보수 지불대상과 메일 알림을 하나의 웹시스템에서 관리한다.

초기에는 기존 구매 ON 데이터를 이관하지 않는다. 대신 향후 구매 ON 및 과거 구매 데이터를 Excel로 업로드할 수 있는 이관 기능의 기반만 구현한다.

개발 순서는 다음과 같다.

1. 로컬 컴퓨터에서 화면·프로세스 검증
2. Supabase 데이터베이스·Storage·권한 구조 연결
3. Outlook 메일 발송 테스트
4. Vercel Preview 배포
5. 운영 데이터와 정책을 확인한 후 Production 배포

## 2. 목표와 성공 기준

### 2.1 목표

- 구매요청 한 건에 여러 상품을 등록한다.
- 상품별로 여러 공급사 견적과 가격을 등록한다.
- Buyer가 원가를 입력하면 운영원가·Guide Price·List Price가 자동 계산된다.
- 요청자는 운영원가·Guide Price·List Price를 확인하되 원가는 메일에서 노출하지 않는다.
- 팀장은 기본 승인 담당자로 동작한다.
- Buyer만 구매 Status를 변경할 수 있다.
- 담당 카테고리에 따라 Buyer가 자동 배정된다.
- 월별 지불대상은 매월 20일 기준으로 관리한다.
- 계약 만기 알림은 해당 Buyer에게 발송한다.
- 첨부파일은 파일당 최대 10MB까지 허용한다.

### 2.2 성공 기준

- 요청자가 3분 이내에 구매요청을 등록할 수 있다.
- Buyer가 한 요청에 2개 이상의 상품과 상품별 2개 이상의 견적을 저장할 수 있다.
- 승인·상태·가격 변경 이력이 모두 남는다.
- 권한 없는 사용자의 원가 조회·메일 노출이 차단된다.
- Status 변경 시 지정된 Outlook 수신자에게 메일이 발송된다.
- 로컬 환경에서 동일한 화면과 프로세스를 재현할 수 있다.
- Vercel Preview 환경에서 Supabase 데이터와 첨부파일을 사용할 수 있다.
- Excel 업로드 전 검증 결과를 사용자에게 보여주고, 오류 행은 저장하지 않는다.

## 3. 사용자와 권한

| 역할 | 주요 권한 |
|---|---|
| 요청자 | 구매요청 생성, 본인 요청 조회, 공개 가격 조회, 첨부파일 등록 |
| Buyer | 담당 카테고리 요청 조회, 견적·가격·번들 관리, Status 변경, 원가 조회, 메일 발송 재시도 |
| 팀장 | 담당 조직의 구매요청 승인·반려, 승인 의견 등록 |
| NP MKT 관리자 | 전체 데이터·사용자·카테고리·마진율·메일 템플릿·업로드 관리 |

초기 로컬 프로토타입에서는 테스트 사용자 전환 기능을 제공한다. 운영 환경에서는 회사 계정 연동을 우선 검토하되, 회사 정책상 불가하면 사내 계정 기반 인증으로 대체한다.

### 3.1 가격정보 권한

- Buyer/관리자: 원가, 운영원가, Guide Price, List Price, Dealer Price 확인
- 요청자: 운영원가, Guide Price, List Price 확인
- 요청자 대상 메일: 원가 원문은 제외하고 `*`로 표시
- 팀장: 승인 화면에서 원가, 운영원가, Guide Price, List Price를 확인한다. 단, 팀장에게 발송되는 메일 본문에서는 원가를 `*`로 표시한다.

원가를 화면에서 숨기는 것과 메일 본문에서 숨기는 것을 별도 정책으로 관리한다. 모든 원가 열람은 감사 로그에 남긴다.

## 4. 시스템 환경과 배포

### 4.1 목표 아키텍처

- Frontend/API: Next.js + TypeScript
- Hosting: Vercel
- Database: Supabase PostgreSQL
- Authentication: Supabase Auth를 기본 어댑터로 사용하고 회사 계정 연동 어댑터를 별도 설계
- File storage: Supabase Storage, 요청·견적·계약별 폴더 분리
- Mail: Outlook을 대상으로 하되 Microsoft Graph는 사용하지 않는다. 회사가 허용하는 SMTP Relay 또는 Outlook/Power Automate 기반 승인된 발송 경로를 사용하고, 개발 단계에서는 메일 미리보기를 제공한다.
- Local: `.env.local` 기반으로 로컬 개발 서버 실행

### 4.2 메일 연동 제약

Microsoft Graph 앱 동의가 불가능하므로 Graph 기반 발송은 구현하지 않는다. 시스템은 메일 발송 어댑터를 분리하고 다음 모드를 지원한다.

1. 개발 모드: 수신자·제목·본문 미리보기와 발송 로그만 생성
2. 운영 후보 1: 회사 승인 SMTP Relay
3. 운영 후보 2: Outlook/Power Automate 등 회사가 승인한 메일 자동화 경로

운영 후보 중 실제 사용 가능한 경로는 회사 IT 정책 확인 후 선택한다.

## 5. 핵심 업무 프로세스

### 5.1 구매요청 흐름

```text
요청자 입력
  ↓
접수/구매진행
  ↓ 팀장 승인
견적완료
  ↓ Buyer 발주 처리
발주중
  ↓ Buyer 쉽컴펌 처리
쉽컴펌 완료
```

`팀장 승인/반려`는 Status와 별도 승인 상태로 관리한다. 따라서 사용자가 요청한 Status 값은 다음 4개를 고정한다.

- 접수/구매진행
- 견적완료
- 발주중
- 쉽컴펌 완료

### 5.2 Status 변경 규칙

- 요청자: 요청 등록 및 보완자료 제출 가능, Status 직접 변경 불가
- 팀장: 승인/반려 가능, Status 직접 변경 불가
- Buyer: Status 변경 가능
- 관리자: 오류 정정 목적의 예외 변경 가능하며 사유 필수
- 정상 흐름을 건너뛰는 변경은 관리자 또는 Buyer의 사유 입력이 필요하다.

### 5.3 요청 필수 입력

| 항목 | 입력 규칙 |
|---|---|
| 요청자 | 로그인 사용자 자동 입력, 수정 불가 |
| 접수날짜 | 저장 시 금일 자동 입력 |
| 납품월 | 필수, 연월 선택 |
| 상품 | 최소 1개, 요청 1건에 여러 상품 가능 |
| Buyer | 상품 카테고리에 따라 자동 입력, 관리자만 수정 가능 |
| 보증기간 | 상품별 입력 |
| 설치 지원 여부 | 예/아니오 |
| 교육 지원 여부 | 예/아니오 |
| 고객명 | 필수 |
| 담당자명 | 필수 |
| 연락처 | 필수, 전화번호 형식 검증 |
| 납품주소 | 필수 |
| 계약 유형 | 단가계약/비단가계약/유지보수 등 코드 관리 |
| 첨부파일 | 선택, 파일당 최대 10MB |

상품명·수량·보증기간·설치·교육 지원 여부는 상품 단위로 저장한다. 고객명·담당자명·연락처·납품주소는 요청 단위로 저장하되, 상품별 예외가 필요할 때 상품 단위로 override할 수 있도록 설계한다.

## 6. 견적·번들·가격 요구사항

### 6.1 데이터 구조

```text
구매요청 1건
 ├─ 요청상품 여러 건
 │   └─ 견적 여러 건
 └─ 번들 여러 건
     └─ 번들 구성품 여러 건
```

### 6.2 견적 필드

- 견적ID, 상품ID, 공급사, 사업자번호
- 견적일, 유효기간, 통화
- 원가, 운영원가, Guide Price, List Price, Dealer Price
- 수량, 총액
- 최종선택 여부
- 견적서·사양서 등 첨부파일
- Buyer 메모 및 요청자 공개 메모

### 6.3 운영원가 엑셀 산식 반영

`운영원가.xlsx`의 확인된 구조를 기준으로 다음을 시스템 계산 규칙으로 정의한다.

시스템의 공식 명칭은 `운영원가`로 통일한다. 화면·메일·데이터베이스 필드에서 `Operating Cost` 등 다른 명칭을 사용하지 않는다.

#### 운영원가

현재 파일의 대표 샘플에서 원가 대비 운영원가는 3.15% 가산 구조로 확인된다.

```text
운영원가 = 원가 × 1.0315
```

최종 구현에서는 이 3.15%를 코드에 고정하지 않고 `가격정책` 테이블의 운영원가 가산율로 관리한다. 정책이 바뀌면 과거 견적의 계산 결과는 유지하고 신규 견적부터 새 정책을 적용한다.

#### Guide Price

운영원가 엑셀의 카테고리별 Guide 마진율을 사용한다.

```text
Guide Price = ROUNDUP(원가 / (1 - Guide 마진율), -3)
```

#### List Price

운영원가 엑셀의 `Information` 시트에서 카테고리별 List Price율을 관리하는 것으로 해석한다.

```text
List Price = ROUNDUP(원가 / (1 - List Price 마진율), -3)
```

List Price율이 `-` 또는 미등록이면 List Price를 계산하지 않고 화면·메일에서 표시하지 않는다. 해당 셀은 공란 또는 `-`가 아닌 `미표시` 상태로 처리한다.

#### Dealer Price

Dealer Price는 Buyer/관리자 화면에서만 보이며, 운영원가 엑셀의 Dealer 마진율을 적용한다.

```text
Dealer Price = ROUNDUP(원가 / (1 - Dealer 마진율), -3)
```

모든 산식에는 적용된 가격정책 버전과 적용일을 저장한다.

## 7. Buyer·카테고리 자동 매핑

첨부 `NPP 업무 분장 20260406.pptx`를 초기 기준정보로 사용한다.

| Buyer | Main Category | Sub Category |
|---|---|---|
| 김진영 | ARIBA 비용·시스템 운영/교육, 도급 DOS/MPS, 범용 SW, 출력물, 광고 | PC, 여행, 행사, 판촉물, 이벤트, 용지 |
| 김정모 | 문서보안솔루션, 자산관리솔루션, 오피스 커뮤니케이션, 화상회의 장비, 공사, Bundle 재고 | 저장장치, 네트워크, ESET, 업무·문서 자동화 |
| 이한식 | PC Rental, PC 판매, 저장장치 | Server/NAS, 카드리더기, 가구, 가전, 간판, 사무용품 |
| 이동규 | 인쇄 후가공기, 오피스환경, 카드리더기, ESET | 범용 SW, 홍보, 영상제작 |
| 신민경 | Server, NAS, 용지, 특수지 | 후처리기, 출력물 |
| 김희균 | 네트워크, 업무자동화 솔루션, 문서자동화 솔루션, 판촉·여행·행사 | 문서보안, 자산관리, 오피스 커뮤니케이션, 화상회의, 공사, CCTV, 인테리어 |

### 7.1 매핑 우선순위

1. 관리자가 등록한 세부 카테고리 직접 매핑
2. Main Category 매핑
3. Sub Category 매핑
4. 매핑 실패 시 NP MKT 관리자에게 재배정 요청

카테고리 중복 매칭이 발생하면 시스템은 임의 배정하지 않고 `Buyer 결정 필요` 상태로 둔다. 요청자의 조직 팀장이 최종 Buyer를 지정하며, 지정 결과와 변경 이력을 기록한다. 관리자는 데이터 오류 정정 또는 팀장 요청에 따른 예외 처리를 할 수 있다.

## 8. 승인과 감사로그

- 기본 승인 담당자는 요청자의 조직 팀장이다.
- 팀장 정보는 조직·사용자 기준정보에서 조회한다.
- 팀장이 부재하거나 자기 요청인 경우 관리자가 대체 승인자를 지정한다.
- 승인·반려 시 의견, 승인자, 일시를 기록한다.
- 가격 수정, Buyer 재배정, Status 예외 변경, 원가 열람, 파일 삭제는 감사로그를 생성한다.

## 9. Outlook 메일 요구사항

### 9.1 발송 이벤트

| 이벤트 | To | Cc | 원가 표시 |
|---|---|---|---|
| 요청 접수 | Buyer, 팀장 | 요청자 | 요청자 수신본은 원가 `*` |
| 팀장 승인/반려 | 요청자, Buyer | 팀장 | 요청자 수신본은 원가 `*` |
| 견적완료 | 요청자 | Buyer, 팀장 | 원가 `*`, 운영원가·Guide·List 공개 |
| 발주중 | 요청자 | Buyer, 팀장 | 원가 `*` |
| 쉽컴펌 완료 | 요청자 | Buyer, 팀장 | 원가 `*` |
| 만기 임박 | Buyer | NP MKT 관리자 | Buyer는 원가 확인 가능 |
| 메일 실패 | 관리자 | - | 실패 사유 포함 |

### 9.2 메일 템플릿

메일 제목 형식:

```text
[NP MKT 구매] {요청번호} · {상품명} · {Status}
```

본문 공통 구성:

1. 요청번호·현재 Status·변경일시
2. 요청자·고객명·납품월·Buyer
3. 상품 목록 및 수량
4. 요청자 공개 가격: 운영원가·Guide Price·List Price
5. 원가: 요청자 메일에서는 `*`, Buyer/관리자 메일에서는 원문
6. 첨부파일·시스템 바로가기
7. 다음 담당자와 처리기한

메일 템플릿은 관리자 화면에서 버전 관리하며, 발송 전 미리보기와 테스트 발송을 제공한다.

## 10. 구독·유지보수와 월별 지불

- 월별 지불대상 기준일: 매월 20일
- 계약 청구주기별로 해당 월 지불 후보를 생성
- 지불 후보는 예정·자료요청·검토중·처리완료·대상외 상태로 관리
- 계약 만기 알림 수신자: 해당 Buyer
- 만기 알림 기준: 90일·60일·30일·만료
- 계약서·견적서·활동내역서·인보이스 첨부 지원
- Ariba/ERP 직접 연동은 PRD 범위에서 제외하고, 향후 Excel 다운로드 또는 API 연동을 위한 데이터 구조만 제공

## 11. Excel 업로드

초기에는 기존 구매 ON 데이터를 자동 이관하지 않는다. 대신 관리자 메뉴에서 다음 형식의 Excel 업로드 기능을 제공한다.

- 구매이력 업로드
- 업체 마스터 업로드
- 사용자·조직·Buyer 업로드
- 카테고리·Buyer 매핑 업로드
- 계약·구독 업로드

업로드 절차:

1. 템플릿 다운로드
2. Excel 파일 선택
3. 열·필수값·날짜·금액·중복키 검증
4. 오류 행 목록과 수정 안내 표시
5. 미리보기
6. 관리자 승인 후 저장
7. 업로드 배치ID·파일명·실행자·결과 건수 기록

파일 업로드 자체는 10MB 제한을 적용하고, 데이터 행 수 제한은 별도 운영 설정으로 관리한다.

## 12. 첨부파일

- 파일당 최대 10MB
- 요청·상품·견적·계약·지불대상별 첨부
- 허용 확장자: PDF, XLSX, XLSM, DOCX, PPTX, PNG, JPG, ZIP
- 파일명, 크기, 업로더, 업로드일시, 파일 유형, 삭제일시 기록
- 실제 삭제 대신 논리 삭제를 기본으로 한다.
- Storage에는 권한 검증 후 signed URL로 접근한다.

## 13. 주요 화면

1. 로그인/테스트 사용자 선택
2. 대시보드: 접수·견적완료·발주중·쉽컴펌, 만기알림, 월별 지불
3. 구매요청 목록: 역할·Status·기간·Buyer 필터
4. 구매요청 등록/상세: 필수정보·상품 여러 건·첨부
5. Buyer 견적관리: 상품별 다중 견적, 가격 계산, 최종선택
6. 번들관리: 번들 생성·구성품 추가·번들코드
7. 승인함: 팀장 승인/반려·의견
8. 계약관리: 계약기간·청구주기·만기알림
9. 월별 지불대상: 매월 20일 기준 후보·증빙·처리상태
10. Excel 업로드: 템플릿·검증·미리보기·배치 이력
11. 코드/권한/메일 템플릿 관리: 관리자 전용

## 14. 데이터 모델 초안

- `users`: 사용자, 이메일, 부서, 팀, 역할, 활성 여부
- `teams`: 조직, 팀장, 대체 승인자
- `categories`: Main/Sub Category, 활성 여부
- `buyer_category_mappings`: Category-Buyer 매핑, 우선순위, 적용기간
- `pricing_policies`: 원가 가산율, Guide/List/Dealer 마진율, 버전, 적용일
- `purchase_requests`: 요청 기본정보, 팀장 승인상태, 현재 Status
- `request_items`: 상품, 수량, 납품·설치·교육·보증 정보
- `quotes`: 공급사별 견적·원가·공개가격·최종선택
- `bundles`: 번들 헤더
- `bundle_items`: 번들 구성품
- `attachments`: Storage 메타데이터와 연결 대상
- `status_histories`: Status 변경 이력
- `approvals`: 팀장 승인/반려 기록
- `contracts`: 구독·유지보수 계약
- `payment_targets`: 월별 지불대상
- `mail_templates`: 메일 템플릿 버전
- `mail_logs`: 수신자·발송상태·실패사유
- `import_batches` / `import_errors`: Excel 업로드 이력
- `audit_logs`: 권한·가격·Status·파일 관련 감사로그

## 15. 비기능 요구사항

- 원가 데이터는 서버 측 권한 검증 후 반환한다. 프론트엔드 숨김만으로 보안을 구현하지 않는다.
- 모든 API는 사용자 역할과 데이터 범위를 검증한다.
- 첨부파일 URL은 공개 URL이 아닌 만료형 signed URL을 사용한다.
- 시간은 서버에서 Asia/Seoul 기준으로 저장·표시한다.
- 금액은 통화와 소수점 자릿수를 함께 저장한다.
- 모든 주요 변경은 생성자·수정자·일시를 저장한다.
- 로컬·Preview·Production 환경의 데이터베이스와 Storage 버킷을 분리한다.
- Production 배포 전 가격 산식, 권한, 메일 마스킹, 첨부파일 접근을 별도 테스트한다.

## 17. 테스트 요구사항

### 기능 테스트

- 필수값 누락 방지
- 금일 접수날짜 자동 입력
- 카테고리 기반 Buyer 자동 배정
- 중복 카테고리 매칭의 관리자 재배정
- 팀장 승인/반려
- Buyer 외 Status 변경 차단
- 다중 상품·다중 견적·다중 번들
- 원가 입력 후 세 가격 자동 계산
- 요청자 메일의 원가 `*` 마스킹
- 10MB 초과 첨부파일 거부
- 매월 20일 지불대상 생성
- 90/60/30일 만기알림
- Excel 오류 행 검증 및 배치 롤백

### 보안 테스트

- 요청자가 다른 요청의 원가를 조회할 수 없는지
- 일반 API 호출로 원가 필드를 우회 조회할 수 없는지
- signed URL 만료 후 파일 접근이 차단되는지
- Buyer가 담당 범위 밖 데이터를 수정할 수 없는지
- 관리자 외 사용자가 가격정책·메일템플릿을 수정할 수 없는지

## 18. 확인 필요 정책

구현 시작 전에 다음 3가지를 확정한다.

1. 운영원가 3.15% 가산율의 공식 적용 범위와 변경 승인자
2. 회사가 허용하는 Outlook 메일 발송 경로: SMTP Relay 또는 Outlook/Power Automate
3. 팀장 부재·자기 요청 시 대체 승인자 지정 규칙

이 항목들은 화면 프로토타입을 막지는 않지만, 운영 배포 전 반드시 확정해야 한다.
