# NP MKT 구매 업무 통합 시스템 설계

작성일: 2026-08-14  
대상 조직: NP MKT 구매 업무팀  
문서 상태: 사용자 승인 설계안

## 1. 목적과 범위

NP MKT의 구매 요청, 번들 견적, 구매이력, 구독·유지보수 계약과 월별 지불대상을 하나의 사내 전용 웹시스템에서 관리한다. 기존 구매 ON의 업무 흐름과 메일 알림은 유지하되, 다중 가격·다중 번들·다중 첨부와 권한 기반 원가 보호를 제공한다.

1단계에서는 Ariba/ERP 직접 연동을 구현하지 않는다. 대신 월별 지불대상과 처리상태를 관리하고, 파일 생성·API 연동은 후속 단계로 둔다.

## 2. 현행 자료에서 확인된 문제와 자산

- 구매 ON 매뉴얼의 상태 흐름: 견적의뢰중 → 견적입수완료 → 번들코드생성중 → 가격등록증 → IDMP승인중/완료 → 발주중 → 쉽컴펌완료
- 현재 구매 ON은 상품·가격·번들정보가 단일 세트 중심이며, 견적 사양 첨부도 1개 파일 제한이 있다.
- 구매이력 엑셀 `NPP추진팀 CD집계표 및 공수표_New_개인관리용.xlsx`의 `CD집계표(Total)`은 약 3,800행 규모이며 요청·발주·검수·세금계산서·카테고리·공급사·Buyer 정보를 포함한다.
- 구독 템플릿은 계약기간, 청구주기, 통화, 단가·수량, 자동갱신, 잔여일수, 만기 알림 계산을 이미 포함한다.
- 유지보수 엑셀은 `유지보수지불건`과 `Ariba입력대상` 중심으로 월별 지불대상, 활동내역서, 인보이스, 계정·Cost Center를 관리한다.
- 기존 Power Apps/SharePoint 목록과 첨부파일은 Export 및 이관이 가능하다.

## 3. 권장 구축 방향

목표는 사내 전용 통합 웹시스템이다. 실제 구축은 다음 단계로 나누어 리스크를 낮춘다.

1. 구매 ON 개선과 데이터 기반 구축
2. 과거 구매이력 통합검색·분석
3. 구독·유지보수·월별 지불대상 관리
4. Ariba/ERP 입력파일 자동생성 및 API 연동(후속)

인증은 회사 계정 기반 연동을 우선 검토한다. 회사 정책상 연동이 불가하면 사내 전용 계정과 역할 기반 권한으로 대체한다. 배포와 접근은 사내망 전용을 기준으로 한다.

## 4. 전체 구조

```text
사내 사용자
   ↓
사내 전용 웹시스템
   ├─ 구매요청·견적·번들
   ├─ 구매이력 조회·분석
   ├─ 구독·유지보수 계약
   └─ 월별 지불대상 관리
        ↓
통합 데이터베이스
   ├─ 구매 ON SharePoint 이관 데이터
   ├─ 구매 엑셀 과거 데이터
   ├─ 계약·구독 데이터
   └─ 업체·조직·코드 데이터
```

핵심 설계 원칙은 다음과 같다.

- 업무 객체를 구매요청, 요청상품, 견적, 번들, 계약, 지불대상으로 분리한다.
- 기존 원본 데이터는 보존하고, 표준화된 검색·집계 데이터와 분리한다.
- 원가는 원문으로 저장하되 화면·메일·검색 결과의 노출은 역할별로 제어한다.
- 상태 변경은 이력으로 남기고, 상태별 알림 규칙은 코드화한다.
- 계약에서 월별 지불대상을 생성하되 담당자가 검토·확정하도록 한다.

## 5. 사용자와 권한

| 역할 | 주요 권한 |
|---|---|
| 요청자 | 본인 구매요청 등록·조회, 공개 가격정보 확인 |
| Buyer | 담당 카테고리의 상품·견적·번들·발주 처리, 원가 확인 |
| 팀장/승인자 | 승인 및 주요 상태 확인 |
| NP MKT 관리자 | 전체 데이터·코드·권한·알림 규칙 관리, 원가 확인 |
| 일반 조회자 | 허용된 구매이력과 집계 조회 |

권한은 사용자, 조직, 담당 카테고리, 데이터 소유권을 함께 고려한다. 메일은 수신자 역할에 따라 원가를 원문 또는 `*`로 표시한다.

## 6. 구매요청·견적·번들

### 6.1 데이터 구조

```text
구매요청 1건
 ├─ 요청상품 여러 건
 │   └─ 상품별 견적 여러 건
 └─ 번들 여러 건
     └─ 번들 구성품 여러 건
```

구매요청에는 요청번호, 요청자, 부서, 고객, 구매용도, 요청일, 전체 상태를 저장한다. 요청상품에는 상품명, 제조사, 모델명, 주요사양, 수량, 희망납기, 담당 Buyer를 저장한다.

견적에는 공급사, 원가, 운영원가, 가이드가, 딜러가, 통화, 유효기간, 견적서와 사양서 첨부를 저장한다. Buyer는 상품별로 여러 업체의 견적을 추가하고 최종 선택을 표시할 수 있다.

번들은 번들명, 번들코드, 구성품, 판매가, 원가, 최종 선택 여부를 관리한다. 첨부파일은 견적서·사양서·계약서 등 파일 유형을 구분하고 여러 개 등록할 수 있다.

### 6.2 상태와 알림

기존 상태 흐름을 유지하되 요청·상품 단위 상태를 지원한다.

`견적의뢰중 → 견적입수완료 → 번들코드생성중 → 가격등록증 → IDMP승인중 → IDMP승인완료 → 발주중 → 쉽컴펌완료`

모든 상태 변경은 변경 전 상태, 변경 후 상태, 변경자, 변경일시, 변경사유를 기록한다. 접수, 견적완료, 발주, 쉽컴펌, 반려·재작업, 견적 유효기간 임박, 처리 지연을 알림 이벤트로 관리한다.

메일에는 요청번호, 상품명, 상태, 시스템 링크와 공개 가능한 가격정보만 포함한다. 원가 권한이 없는 수신자에게 원가는 항상 `*`로 표시한다.

## 7. 구매이력 조회·분석

기존 `CD집계표(Total)` 원본 컬럼은 원본 이력으로 보존하고, 조회용 표준 컬럼을 별도 관리한다. 공급사명, 사업자번호, 카테고리명처럼 표기가 다른 값은 표준 코드로 매핑한다.

검색 조건은 다음을 포함한다.

- 구매요청번호, PO번호, 주문번호
- 세금계산서일, 발주일, 검수일 및 기간
- 요청자, 부서, Buyer
- 고객명, 공급사, 제조사
- Main/Sub Category, 상태, 구매용도, Action Item
- 상품명, 모델명, 규격, 금액 범위
- 계약·유지보수 여부

결과에는 진행상태, 품목·수량·단가·총액, 공급사, 업체선정기준, 고객·부서·Buyer, 첨부파일, 상태이력, 동일 품목의 과거 가격을 표시한다.

요약 화면은 월별 구매금액, Buyer별 처리건수·금액, Category별 구매금액, 공급사별 구매실적, 고객별 실적, 진행 지연·미완료 건을 제공한다.

## 8. 구독·유지보수·월별 지불대상

계약 기본정보는 거래처·사업자번호, 솔루션·벤더, 구분, 담당자, 시작·종료일, 청구주기, 통화, 단가·수량, 공급가액·부가세·합계, 결제방식, 자동갱신, 해지 통보기한, 첨부파일을 포함한다.

시스템은 잔여일수, 갱신상태, 연간 환산비용, 다음 청구 예정월, 해당 월 지불대상 여부를 계산한다. 만기 알림은 90일 사전검토, 60일 주의, 30일 긴급, 만료 단계로 관리하며 동일 알림의 중복 발송을 방지한다.

계약의 청구주기와 지불월을 기준으로 월별 지불대상 후보를 자동 생성한다. 담당자는 지불 예정금액, 인보이스 번호, 세금계산서일, 활동내역서, 고객·Cost Center·계정, 지불상태, 처리일과 비고를 확인·수정한다.

지불상태는 `예정 → 자료요청 → 검토중 → 처리완료`와 `대상외`를 사용한다. 1단계에서는 Ariba/ERP에 직접 전송하지 않으며, 기존 엑셀과 병행 검증한다.

## 9. 데이터 이관

이관 대상은 다음과 같다.

- 구매 ON SharePoint 목록과 첨부파일
- 구매이력 엑셀의 원본 및 표준화 데이터
- 업체·조직·Buyer·카테고리 코드
- 구독·유지보수 계약 및 과거 지불 처리내역

이관 검증은 건수, 금액 합계, 주요 상태별 건수, 기간별 합계, 첨부파일 연결 건수를 비교한다. 원본 파일은 검증 완료 전까지 보존하고, 표준화 실패 데이터는 별도 오류 목록으로 관리한다.

## 10. 구축 단계

### 1단계

인증·권한, 구매 ON 데이터 이관, 구매요청·다중 상품·다중 견적·다중 번들, 다중 첨부, 원가 마스킹, 상태이력과 메일 알림을 구현한다.

### 2단계

과거 구매이력 이관, 공급사·카테고리 표준화, 통합검색, 동일 품목 가격 비교, Buyer·부서·고객·월별 통계를 구현한다.

### 3단계

계약 등록, 자동갱신·해지통보기한, 만기 알림, 월별 지불대상 생성, 증빙자료와 처리상태를 구현한다.

### 후속 단계

Ariba 입력파일 자동생성, ERP/Ariba API, 결재·전자서명, 예산 대비 실적과 고급 분석을 검토한다.

## 11. 검증 기준

- 기존 구매 ON 진행 건이 누락 없이 조회된다.
- 하나의 요청에 여러 상품·견적·번들을 등록할 수 있다.
- 권한 없는 사용자는 화면·메일·검색 결과에서 원가를 볼 수 없다.
- 상태 변경 시 해당 담당자에게 정확히 한 번 알림이 발송된다.
- 과거 엑셀 데이터의 건수와 금액 합계가 시스템 집계와 일치한다.
- 계약 청구주기별 지불대상이 정확히 생성된다.
- 만기 알림이 기준일과 대상자에 맞고 중복 발송되지 않는다.
- 첨부파일과 상태변경 이력이 요청·계약에 연결된다.
- 사내망에서 허용된 사용자가 안정적으로 접근한다.

## 12. 범위 밖 항목

1단계 범위에는 Ariba/ERP 직접 연동, 전자결재·전자서명, 외부망 공개, 고급 예산 통제, 자동 이메일 회신 분석을 포함하지 않는다. 해당 항목은 핵심 데이터 구조와 권한 모델이 안정화된 후 후속 범위로 검토한다.
